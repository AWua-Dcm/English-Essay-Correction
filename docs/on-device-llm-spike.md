# 实测：浏览器内本地模型能否批改（结论：不能）

这次实测是为了回答一个具体问题：**能不能让网页自己批改、免 Key、且手机能用？**
路线是 WebLLM + WebGPU，在浏览器内跑一个小模型。

## 实测条件

| 项 | 值 |
|---|---|
| 模型 | Qwen2.5-1.5B-Instruct-q4f16_1（约 1GB） |
| 运行时 | WebLLM 0.2.86 / WebGPU / 真实 Chrome |
| 硬件 | RTX 5060 Laptop |
| 题目 | 四篇同题作文，真实给分 11 / 8 / 5 / 2 |

基准选这四篇，是因为它们是最锋利的测试：**连排序都做不到的模型，不配批改。**

## 结果

| 真实分 | 模型给分 | 模型给的四项分 |
|---|---|---|
| 11 | 11 | 4 / 3 / 2 / 2 |
| 8 | **12** | 4 / 3 / 2 / 2 |
| 5 | **10** | 4 / 3 / 2 / 2 |
| 2 | **12** | 4 / 3 / 2 / 2 |

**模型对四篇给出了完全相同的分项（4/3/2/2）**，只把总分做了抖动。那篇 2 分的作文
（语法近乎瓦解）被判成 **12/15**，与 11 分的作文几乎同分。**排序错误。**

这不是标尺的问题——模型根本没有在区分文本，它输出的是一个固定模板。
1.5B 低于这类任务的能力下限。

## 附带实测出的工程数据

| 项 | 实测 |
|---|---|
| 模型加载 | **221 秒 / 约 1GB**（桌面 + 光纤） |
| 单篇推理 | 约 2.1 秒（这部分不是瓶颈） |
| 权重可用源 | 魔搭 modelscope.cn（支持 Range 206） |
| WASM 模型库可用源 | fastly.jsdelivr.net/gh |
| **不可用源** | huggingface.co、raw.githubusercontent.com、cdn.jsdelivr.net 全部 000；**hf-mirror 虽然 curl 能看到 CORS 头，浏览器仍拒绝** |

## 对"手机能用"意味着什么

即便不考虑质量，手机上还有三道过不去的坎：

1. **微信内置浏览器**：查不到 WebGPU 支持证据，安卓微信走 XWeb 内核、Chromium 版本落后
2. **iOS**：Safari 26 / iOS 26 才完整支持，旧版没有
3. **安卓**：需 Android 12+ 且 GPU 兼容；外加首次约 1GB 下载、推理占 1.5–2GB 内存

而质量这一关（上表）在桌面、在有独显的机器上就已经没过。

## 结论

**浏览器内小模型批改这条路不可行**，原因不只是工程摩擦，而是模型能力不足：
1.5B 在这个任务上退化成输出常量。

一个前沿大模型 + 同样的标尺，实测精确档位一致率也只有 44%；指望 1.5B 做同一件事
不现实。要提升只能上更大的模型，而更大的模型在手机上更不可能跑。

**四条要求（免 Key / 网页自己算 / 手机能用 / 评分可信）无法同时满足。**
本项目的既有两条路径（复制模式、自动模式）已经覆盖了前三条中的不同组合：
复制模式满足免 Key + 手机能用 + 可信，自动模式满足网页自己算 + 手机能用 + 可信。
