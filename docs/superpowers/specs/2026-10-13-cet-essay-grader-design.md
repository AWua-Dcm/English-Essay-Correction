## 1. 背景与目标

用户提供了一套完整的"大学英语四六级作文阅卷导师"批改流程（4 个步骤 + 7 条硬性要求，见附录 A，下称"批改模板"），要求做成一个**可复用的网页工具**并部署到 GitHub Pages。

**目标**：任何人打开网页即可使用——粘贴或上传作文 → 得到严格按批改模板产出的批改报告（评分卡 + 步骤①②③④全文），可导出、可存档、可分享。

**核心原则**

1. **批改逻辑与批改模板逐字一致**（附录 A 为唯一正本）；模板边界规则见 §6.1。
2. **零后端、零构建、零 CDN 依赖**：纯静态文件，任何静态托管都能跑；不引用任何 CDN（jsdelivr 等在国内不稳）。
3. **数据全部留在用户浏览器本地**；除用户主动选择的大模型 API 外，无任何网络请求。
4. **确定性优先**：所有解析、渲染、网络、错误路径均按"真实模型会违约、真实网络会抖动"设计；宁可显式降级并给出可执行的下一步，也不静默出错或假成功。
5. **公共承诺必须与能力一致**：页面文案、README 中对"免 Key 可用范围"的表述必须与实现逐一对应（见 §2.3）。

## 2. 用户与典型场景

### 2.1 用户与模式

- 主要用户：需要四六级作文反馈的学生（**手机为主要使用设备**）；教师 / 助教用来生成批改报告。
- 场景 A（自动模式）：用户配置了自己的大模型 API Key → 页内一键批改，流式输出。
- 场景 B（复制模式，免 Key）：没有 Key → 网页组装完整批改指令，一键复制到任意 AI 聊天服务 → 把结果粘回网页 → 得到同样排版精美的报告。

### 2.2 成本说明

| 环节 | 复制模式（免 Key） | 自动模式（有 Key） |
|---|---|---|
| 网页本身 | 零调用、零费用 | 零费用 |
| 批改执行 | 由用户所用的免费 AI 聊天服务完成，无 API 费用 | 按服务商计费（DeepSeek 一篇约几分钱，以官方价目为准） |
| 托管 | GitHub Pages 免费 | 同左 |

### 2.3 "免 Key 可用范围"的准确表述（硬性文案，页脚与 README 一致）

> 免 Key 也能批改（复制模式），全程免费。图片作文在复制模式下：请把作文照片**直接发送到你所用的 AI 对话**里（推荐 Kimi / 豆包 / 通义等支持看图的免费服务），本页上传的照片只作预览与记录，不会离开你的浏览器。

### 2.4 典型场景 A/B 的图片分支

- 自动模式 + 图片：需所选服务商预设支持视觉（§6.2 标注）。
- 复制模式 + 图片：本页上传仅用于（a）生成正确的指令文本（"见对话中的照片 N 张"）、（b）界面提示；（b）照片由用户自行在外部 AI 对话中附上。推荐服务按"有无图片"分流（§9.3）。

## 3. 范围

### 3.1 做

1. 双模式批改（自动 + 复制），两模式共用同一提示词组装、渲染、评分卡、导出与历史逻辑。
2. 可视化评分卡（总分 /15、档次、四项分项）＋ 四步骤分节报告。
3. 字数统计（四级 120–180 / 六级 150–200）＋ **步骤④优化版本字数的本地核验徽章**（§8）。
4. 图片上传识别（拍照 / 相册；解码-压缩管线见 §6.4）。
5. 导出：打印 / PDF（A4）、Markdown、独立单文件 HTML。
6. 本地历史记录 + **输入草稿持久化**（防手机浏览器回收标签页，§11.3）。
7. 级别：四级 / 六级 / 自动推断（默认）。
8. 服务商预设 + 自定义接口（OpenAI 兼容协议）。
9. 内置示例作文（一键填入）。
10. 结构化输出协议（附录 B）：JSON 分数块 + 容错解析 + 三级降级，保证报告永不静默丢失。
11. 移动端规格与国内环境兜底（viewport、粘性操作条、剪贴板三级降级、微信/QQ 提示、file:// 模式横幅）。

### 3.2 不做（YAGNI）

后端、账号、云同步、多语言界面、题库、自动重批循环、Anthropic 原生协议、统计埋点、深色模式（可在后续版本考虑）、复制模式的自动图片传输（由用户在 AI 对话中自行附图）。

## 4. 技术形态

- 纯静态单页：`index.html` + CSS + 原生 JavaScript。
- **不使用 ES Modules**：普通 `<script>` 按序加载，保证 `file://` 双击可打开（限制见 §5.1.9）。
- **零第三方运行时依赖**；不引用任何 CDN；第三方库一律不进产物。
- Markdown 渲染自研：**先转义、后渲染**白名单渲染器 + **稳定前缀追加式**流式渲染（§7.2）。
- 测试依赖仅 jsdom（devDependency，仅开发期使用）。

### 4.1 硬性约束：相对路径

`index.html` 中所有 `link/script/img` 引用**一律相对路径，禁止以 `/` 开头，禁止写死部署域名绝对 URL**；导出的独立 HTML 不引用任何外部资源。理由：站点部署在项目子路径下（`https://awua-dcm.github.io/English-Essay-Correction/`），根相对路径会让线上全部 404 而本地自测发现不了。此约束有自动化测试（§13.1）。

## 5. 页面结构与交互流

### 5.1 信息架构（单页三区 + 两个抽屉 + 移动端规格）

1. **页头**：产品名"四六级作文 AI 批改台"；副标题"严格对照大学英语四六级官方评分标准 · 四步批改"。
2. **首次引导卡**（可关闭，首次访问或从未配置 Key 时显示）：两条路径图解——① 有 Key → 自动批改（30 秒配置）；② 没 Key → 复制模式（免费，三步：复制指令 → 粘贴到任意 AI → 结果粘回）。
3. **输入区**
   - 级别：三个互斥胶囊按钮——四级 / 六级 / 自动推断（默认，对应硬性要求 6）。
   - 作文题目（选填）。
   - 作文正文 textarea；右下角**实时词数徽章**（文字状态 + 颜色双重表达：`143 · 达标` / `98 · 偏少 22 词` / `214 · 偏多 34 词`；自动推断时显示 `143 词 · 四级 120–180 / 六级 150–200` 不做判定；**纯图片作文时显示 `图片作文 N 张 · 词数以识别结果为准`，绝不显示 0/红色**）。
   - 图片上传：双入口——[拍照]（`capture="environment"`）与 [选择图片]（`accept="image/jpeg,image/png,image/webp"` multiple）；最多 3 张；缩略图 + 删除；压缩处理中显示进度态；解码失败/HEIC 的提示见 §6.4。
   - 操作按钮：[开始批改]（主）、[复制批改指令]（次级；未配置 Key 时**并列为视觉主按钮**）、[填入示例作文]。
   - 模式指示条：真 `<button>`（带边框与箭头，可点性明确）——"自动批改 · DeepSeek"或"复制模式（未配置 Key）"。
   - 移动端规格：`<meta name="viewport" content="width=device-width, initial-scale=1">`；输入控件字号 ≥16px；[开始批改]/[复制批改指令]/词数徽章置于**底部 sticky 操作条**（含 `env(safe-area-inset-bottom)`），软键盘弹出时仍可见可点；textarea 高度用 `dvh`；聚焦时控件滚入可视区。
4. **报告区**（默认隐藏）
   - 顶部 **sticky 分段导航**：评分卡 · ① · ② · ③ · ④（触摸目标 ≥44px）+ [回到顶部]。
   - 评分卡 + 一行说明"四项得分之和即总分；档次为官方分数区间"。
   - 四张步骤分节卡片；步骤④卡内附"优化版 143 词 · 达标（四级要求 120–180）"徽章（§8）。
   - 流式期间：骨架屏 + 已等待秒数 + 常驻 [停止]；提交后 [开始批改] 立即禁用防重复提交（防重复计费）；首 token 超 15 s 追加"模型思考中…"提示。
   - 自动跟随滚动：**仅当用户贴近底部**（<120px）时跟随；用户上翻后停止跟随并显示 [↓ 回到最新] 浮标。
   - 工具条（完成后）：[打印/存为PDF] [导出 .md] [导出 .html] [重新批改]。
5. **设置抽屉**：服务商下拉（自动填充接口与默认模型）、API Key（密码框 + 显隐切换）、模型名（可编辑）、自定义接口地址、[测试连接]、[保存]、[清空全部本地数据]；每行预设下方显示"预设核验日期：YYYY-MM-DD"（§6.2）。
6. **历史记录抽屉**：列表（时间、级别、题目/首句、总分、状态标签：完成/已停止/粘贴导入）；操作：载入报告区、导出、删除、[全部清空]（二次确认）；空态文案"历史仅存本机，建议导出重要报告"。
7. **无障碍基础**：两个抽屉 `role="dialog"` + `aria-modal="true"` + Esc 关闭 + 打开移焦/关闭归还焦点；模式条与操作均为真按钮；词数徽章含文字状态；流式进度用 `aria-live="polite"` 的隐藏状态区播报（开始/结束/已生成字数）。
8. **页脚**：§2.3 的成本文案 + 免责声明（"批改结果由 AI 生成，仅供学习参考，不代表官方评分"）+ 隐私说明（"API Key 与作文内容只保存在你的浏览器；批改内容仅发送给你选择的大模型服务"）。
9. **file:// 模式横幅**：检测 `location.protocol === 'file:'` 时显示常驻小横幅："本地文件模式：批改仍需联网；自动批改可能被浏览器安全策略拦截，建议使用复制模式。"（措辞不得声称"离线可用"）
10. **微信/QQ 内置浏览器提示条**（检出 MicroMessenger / QQ UA 时显示，可关闭）："微信内复制/下载/打印可能受限，建议点右上角 ⋯ → 在浏览器打开。"

### 5.2 主流程

```
填写级别/题目/作文（或图片）
        │
        ├─ 已配置 Key ──▶ [开始批改] ──▶ 流式生成 ──▶ 报告区（评分卡+四步骤）
        │                                              │

## 6. 批改引擎

### 6.1 提示词

**system 消息 = 批改模板正本（附录 A，逐字）+ 输出协议（附录 B，逐字）。**

模板边界规则（防"逐字保留"把输入脚手架混入提示词）：

- **纳入**：附录 A 全部内容（persona 段、"请严格分 4 步执行"段、步骤①~④、硬性要求 1~7）。
- **排除**：输入脚手架行（`【考试级别】：...`、`把学生作文粘贴到这里...` 等占位文案），以及原始消息结尾的编程任务句（"完成后，自行审核网页完成度…推送到 GitHub Pages"）。
- **测试断言**：组装后的提示词不得包含 "GitHub"、"仓库"、"推送" 等仓库管理语言（§13.1）。

**user 消息 = 元信息（三态）+ 作文**：

```
【考试级别】四级
    └─ 变体 A（选四级/六级）：直接写"四级"或"六级"
    └─ 变体 B（自动推断）："未提供，请依据作文内容推断，并先说明你的推断"
【作文题目】志愿者服务的意义          ← 未提供时："未提供，请依据作文内容推断"
【网页统计词数】143 词（四级要求 120-180 词）
    └─ 变体 A（四级/六级 + 有文字）：`143 词（四级要求 120-180 词）`
    └─ 变体 B（自动推断 + 有文字）：`143 词（级别未提供；请按你推断的级别对照达标：四级 120–180 词，六级 150–200 词）`

### 6.3 请求与流式输出（解析契约）

**请求**：`POST {baseURL}/chat/completions`，`Authorization: Bearer {key}`，`stream: true`。

- **token 预算**：`estInput = ceil(全文字符数 / 1.5) + 1500 × 图片数 + 512`；`max_tokens = clamp(min(providerMaxOutput, providerContext - estInput - 512), 512, providerMaxOutput)`。计算值 ≤512 时提示"作文过长或模型上限太小"。
- **参数重试规则**：首次携带 `temperature: 0.6` 与计算出的 `max_tokens`。若 400 且错误涉及参数：第一次仅去掉 `temperature` 重试；仍 400 再去掉 `max_tokens` 重试，并置警告标记——报告尾显示"已移除输出上限参数，输出可能被截断"。（不得静默回落服务端默认上限而用户不知情。）
- **SSE 解析**：`TextDecoder` 单例 + `decode(chunk, {stream: true})`（防 UTF-8 多字节字符跨 chunk 断裂产生乱码）；按 `\n` 行缓冲并 trim `\r`；`data:` 后允许 0/1 个空格；忽略注释行（`: ` 开头）与空行；**任何事件含顶层 `error` 字段立即中止**并按内容映射 §6.6；终止条件三者任一：`[DONE]`、reader done、`finish_reason` 非空。
- **非流式回退**：若响应 `Content-Type` 非 `text/event-stream`（服务商拒绝 stream），把响应体按普通 JSON 解析（同样检查 `choices[0].finish_reason`）。
- **截断检测**：流式取最后一个非空 `finish_reason`，非流式取 `choices[0].finish_reason`；等于 `'length'` → §5.3 截断横幅。
- **停止 / 超时**：`AbortController` 停止；120 s 超时；两者都保留已生成内容并标注（§5.3）。
- **增量渲染**：见 §7.2 稳定前缀追加契约；UI 节流 100 ms。

### 6.4 图片处理（解码-压缩-校验管线）

1. **入口**：[拍照]（`capture="environment"`）与 [选择图片]（`accept="image/jpeg,image/png,image/webp"` multiple，最多 3 张）。
2. **HEIC 预检**：文件名以 `.heic/.heif` 结尾或 MIME 为 `image/heic*` → 立即提示"暂不支持 HEIC，请在相册导出为 JPG，或直接改用复制模式把照片发到 AI 对话"。（iOS 上 `File.type` 可能为空串，不能只靠 MIME。）
3. **解码**：优先 `createImageBitmap(file, {imageOrientation: 'from-image'})`；失败则回退 `Image + objectURL`（EXIF 方向由现代浏览器 drawImage 默认处理；回退路径做方向校验）。解码失败 → §5.3 提示。**解码前大小上限 25MB**（宽进：48MP 手机原图可先解码再压缩，不再直接拒收大文件）。
4. **压缩**：canvas 长边 ≤2048 px、JPEG 质量 0.85；竖拍照片必须方向正确（用方向标记的测试图人工核验）。
5. **空白检测**：压缩后采样像素，若近似纯色（空白/全黑）→ 视为解码异常，报错而非把空白图发给模型。
6. **总量上限**：3 张压缩后 base64 总大小 ≤6MB，超出报错。
7. **多模态消息**：`content: [{type:'text',...}, {type:'image_url', image_url:{url:'data:image/jpeg;base64,...'}}, ...]`。
8. **视觉门控**：选择的服务商/模型不支持视觉时阻止发起（§5.3）。

### 6.5 API Key 与隐私

- 仅存 `localStorage`（`eec.settings.v1`）；密码框默认遮蔽。
- 仅用于向所选服务商发起请求；无任何上报、无第三方请求。
- [测试连接]：`max_tokens: 1` 最小请求；失败文案附"若报模型不存在，可能是服务商已更新模型名，请到其官方文档复制最新模型名填入"。
- [清空全部本地数据]：清除设置、草稿与历史（二次确认）。

### 6.6 错误分类

`api.js` 映射：`auth`（401/403）、`balance`（402）、`rate`（429）、`params`（400，自动重试后）、`network`（fetch TypeError，**措辞不武断**，附原始错误文本与两个行动按钮：检查 Key / 改用复制模式）、`timeout`、`aborted`、`server`（5xx）、`stream_error`（流内 error 事件）、`truncated`（finish_reason=length，非错误路径而是附注）。每个类对应 §5.3 的文案与按钮。

## 7. 输出协议与渲染

### 7.1 分数块解析（`prompt.js`）

1. **定位 JSON**：按序尝试——(a) 全文搜索围栏 ``` ```json / ```JSON / ~~~json（大小写不敏感）且内容含 `"total"` 或 `"status"` 的块；(b) 无围栏时扫描第一个包含 `"total"` 或 `"status"` 的 `{...}` 对象（花括号配对截取）。取第一个命中。解析前做容错：去零宽字符、去首尾空白、截取首 `{` 至末 `}`。
2. **消费后剥离**：解析成功的 JSON 块**从渲染正文、历史存储与导出中全部剥离**（评分卡即其可视化形态）；仅在解析失败时按普通文本保留。
3. **status 处理**：`"unreadable"` → §5.3 警示卡（无评分卡与步骤）。
4. **数值校验**：四个分项必须为整数且 `0≤content≤5、0≤structure≤4、0≤vocab≤3、0≤grammar≤3`；**总分本地重算** `total = content+structure+vocab+grammar`；若模型给的 total 与和不一致 → 采用和不一致时仍显示并加注"（模型给出总分与四项之和不一致，已按四项之和显示）"。
5. **档次本地重算**（不信任模型字符串）：13-15→"13-15分档"；10-12→"10-12分档"；7-9→"7-9分档"；4-6→"4-6分档"；0-3→"1-3分档"。
6. **级别捕获**：JSON 的 `level` ∈ {四级, 六级} 时采用（用于评分卡、打印页眉、导出文件名、历史条目、步骤④字数核验的参照）；缺失时回退用户所选级别；"自动推断"且缺失时记"自动推断"。
7. **备用路径（正则提取）**：对"步骤①"文本做容错正则（容忍 `**`、全/半角冒号、无空格、`分` 后缀、`/15`），提取总分与四项 → 显示评分卡并加注"（解析方式：文本提取）"。
8. **终态降级**：全部失败 → 不显示评分卡，报告完整展示，附"未解析到结构化分数"；绝不静默丢弃报告。
9. **报告结构切分**：按标题行容错匹配（`^#{2,4}\s*步骤\s*[①②③④1-4一-四][^\n]*?(总分|逐条|建议|优化)`）切出四个步骤；未识别到标题时按 §5.3"粘贴不完整"提示条处理（用户可强制渲染）。

### 7.2 Markdown 渲染器（`render.js`）

- **先转义、后渲染**：全文 HTML 转义 → 受限 DOM 生成，永不插入未转义内容。
- **支持子集**：`#`~`####` 标题、`**粗体**`、`*斜体*`、行内代码、围栏代码块、有序/无序列表（含一层嵌套）、`>` 引用块（**含紧随列表项下方的引用行，归入该列表项显示**）、`---` 分隔线、`[文本](http/https)` 链接（新窗口 + `rel="noopener"`）、段落与硬换行。
- **不支持**：表格、HTML 标签、图片（渲染为纯文本）；未知语法按普通文本降级。
- **稳定前缀追加式流式渲染**：以"空行且不在围栏内"为块边界；已完成块**只渲染一次、永不重绘**（保留用户选区与滚动）；每个 tick 仅重渲染最后一个未稳定块（每帧 O(1)）；尾部未闭合的围栏/行内标记自动补全显示。首帧起隐藏分数 JSON 块（§7.1 剥离）。
- 四个步骤标题渲染为分节卡片；其余标题降为样式化小标题。

### 7.3 评分卡

- 总分大字 `/15` + 档次标签（本地重算值）+ 四项分项（名称、得分/满分、进度条）+ 说明行 + 异常注记（和≠total / 正则提取）。
- 评分卡数据同时进入导出与历史。

## 8. 字数统计与步骤④核验

- 统计规则：`[A-Za-z]+(?:['’-][A-Za-z]+)*`（正确处理缩写、连字符）。
- 达标区间：四级 120–180 词；六级 150–200 词（随级别徽章判定；自动推断时不做判定）。
- 统计值注入提示词（§6.1 三态）。
- **步骤④优化版本核验**：按附录 B 的结构固定，取 `### 优化版本正文` 与下一个 `###`/`##` 之间的文本，本地计数 → 步骤④卡、导出、打印与历史中都显示"优化版 N 词 · 达标/偏少/偏多（X 要求 Y–Z 词）"；切片缺失时显示"未标注"（不报错）。
- 历史条目存储 `words`（原作文）与 `optimizedWords`（优化版）。

## 11. 历史与草稿存储（`store.js`）

### 11.1 键设计

- `eec.settings.v1`：设置。
- `eec.draft.v1`：输入草稿（级别、题目、正文、粘贴框原文、图片数量标记；**不含图片数据**）。

### 11.2 配额韧性

写入失败（QuotaExceeded）→ 按时间淘汰最旧条目并重试（循环），仍失败才提示"本地保存失败（存储空间不足），请导出重要报告"；保证后续新记录可写入。删除/清空同步维护索引与分条。

### 11.3 草稿持久化（防手机标签回收）

输入防抖 500ms + `visibilitychange` 时保存；加载时自动恢复并轻提示"已恢复上次输入（图片需重新选择，如有）"。

### 11.4 历史写入时机

自动批改完成、手动停止（标注"已停止"）、粘贴渲染成功，均自动存档；渲染失败不存档。上限 100 条（超出删最旧）。

## 12. 部署运行手册

### 12.1 连通性预检

推送前：`GIT_TERMINAL_PROMPT=0 git ls-remote <远程URL>` 预检（超时 ≥60s，重试 2–3 次；超时=网络问题可重试，401=认证问题转人工，404=远程为空（预期））。已知事实（2026-10-13 实测）：github.com 首次请求曾 15s 超时、随后正常；`raw.githubusercontent.com` 被重置；api.github.com / codeload / github.io 可达。

### 12.2 仓库创建（两条路径）

- **默认路径（推荐，确定性最高）**：请用户在浏览器点 New repository——名称 `English-Essay-Correction`、**公开**（免费版 Pages 要求公开）、**不勾任何初始化文件**（不勾 README/.gitignore/license）。创建后用 §12.1 预检验证"远程为空且 URL 精确等于 `https://github.com/AWua-Dcm/English-Essay-Correction.git`"。
- **自动化路径（仅当用户明确同意）**：用本机 GCM 凭据调 GitHub API。执行纪律：(1) `git credential fill` 取出令牌**只注入环境变量，绝不回显/写日志**，用后 unset；(2) 先 `GET /user` 断言 `login == AWua-Dcm` 且 `X-OAuth-Scopes` 含 `repo`；(3) 建仓请求体固定 `{"name":"English-Essay-Correction","private":false,"auto_init":false}`，创建后断言返回体 `owner.login` 与 `private == false`；(4) 任一步 401/403/422（含权限策略拒绝）→ 立即转默认路径并向用户报告实际采用路径；(5) 令牌过期时请用户完成浏览器登录（含 2FA）后重试。
- **首推恢复**：若远程已存在提交（用户建仓时误加 README），**先与用户确认**，再 `git push --force origin main`。
- 自动化命令统一加 `GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never`（缺凭据快速失败而非弹窗挂起）；失败请用户完成 GCM 登录后重试。

### 12.3 推送

`git push -u origin main`；遇网络错误自动重试 2 次（间隔 10–20s）；成功后 `ls-remote` 复核远端 main 存在。

### 12.4 启用 Pages（顺序依赖：先 push 成功）
