## 1. 背景与目标

用户提供了一套完整的"大学英语四六级作文阅卷导师"批改流程（4 个步骤 + 7 条硬性要求，下称"批改模板"），要求做成一个**可复用的网页工具**并部署到 GitHub Pages。

**目标**：任何人打开网页即可使用——粘贴或上传作文 → 得到严格按批改模板产出的批改报告（评分卡 + 步骤①②③④全文），可导出、可存档、可分享。

**核心原则**

1. 批改逻辑与用户的批改模板**逐字一致**（4 个步骤、全部硬性要求原样保留），不擅自增删评分口径。
2. 工具**零后端、零构建、零 CDN 依赖**：整个应用是纯静态文件，任何静态托管都能跑，国内网络环境下也不受 CDN 波动影响。
3. 数据全部留在用户浏览器本地；除用户主动选择的大模型 API 外，没有任何网络请求。

## 2. 用户与典型场景

- 主要用户：需要四六级作文反馈的学生；教师 / 助教用来快速生成批改报告。
- 场景 A（自动模式）：用户配置了自己的大模型 API Key → 页内一键批改，流式输出，逐字显示。
- 场景 B（复制模式，免 Key）：没有 Key → 网页组装好完整批改指令，一键复制到任意 AI 聊天服务（DeepSeek 网页版 / Kimi / 豆包 / 通义 / ChatGPT 免费版）→ 把结果粘回网页 → 得到同样排版精美的报告。

**成本说明（用户确认过的问题）**

| 环节 | 复制模式（免 Key） | 自动模式（有 Key） |
|---|---|---|
| 网页本身 | 零调用、零费用 | 零费用 |
| 批改执行 | 由用户所用的免费 AI 聊天服务完成，无 API 费用 | 按服务商计费（DeepSeek 一篇约几分钱，以官方价目为准） |
| 托管 | GitHub Pages 免费 | 同左 |

结论：**不配置 Key 也能完整使用全部功能，且全程免费**。此说明必须出现在 README 与网页页脚。

## 3. 范围

### 3.1 做（已确认）

1. 双模式批改：自动模式（浏览器直连大模型 API）+ 复制模式（免 Key）。
2. 可视化评分卡：总分 /15、所属档次、四项分项得分（内容 5 / 结构 4 / 词汇 3 / 语法 3）。
3. 字数统计：本地精确统计词数，对照四级 120–180 / 六级 150–200 实时提示。
4. 图片上传识别作文（依赖所选模型的视觉能力）。
5. 导出：打印 / PDF（A4 打印样式）、Markdown、独立单文件 HTML。
6. 本地历史记录（localStorage，可回看 / 导出 / 删除 / 清空）。
7. 考试级别支持 四级 / 六级 / 自动推断（对应批改模板硬性要求第 6 条）。
8. 服务商预设 + 自定义接口地址（OpenAI 兼容协议）。
9. 内置示例作文（一键填入，用于试用和验证）。

### 3.2 不做（YAGNI，明确排除）

后端服务、账号系统、云同步、多语言界面、题库浏览、自动重批循环、Anthropic 原生协议、任何统计 / 埋点。

## 4. 技术形态

- **纯静态单页**：`index.html` + CSS + 原生 JavaScript。
- **不使用 ES Modules**：用普通 `<script>` 标签按序加载，保证 `file://` 双击打开也能运行（便于离线使用与本地测试）。
- **零第三方运行时依赖**：不引用任何 CDN；不内置任何第三方库。
- **Markdown 渲染自研**：采用"先转义、后渲染"的白名单渲染器（详见 §7.2）。批改报告的结构由我们自己的提示词输出协议约定（§6.1），渲染面可控，自研渲染器同时天然消除 AI 输出注入 XSS 的风险。
- **测试依赖仅 jsdom**（devDependency，仅开发期使用，不进产物）。

## 5. 页面结构与交互流

### 5.1 信息架构（单页三区 + 两个抽屉）

1. **页头**：产品名"四六级作文 AI 批改台"，副标题"严格对照大学英语四六级官方评分标准 · 四步批改"。
2. **输入区**
   - 级别选择：三个互斥胶囊按钮——四级 / 六级 / 自动推断（默认"自动推断"）。
   - 作文题目（选填，单行输入）。
   - 作文正文（大文本框；右下角**实时词数徽章**：选四级显示 `n / 120–180`，选六级 `n / 150–200`，自动推断时只显示词数与两档要求、不做达标判定；颜色区分达标 / 偏少 / 偏多）。
   - 图片上传：拖拽或点击选择，最多 3 张；选择后显示缩略图与删除按钮；原图 > 8MB 时拒绝并提示；上传区下方注明"图片识别需要所选模型支持视觉"。
   - 操作按钮：[开始批改]（主按钮）、[复制批改指令]、[填入示例作文]。
   - 模式指示条：显示当前模式（"自动批改 · DeepSeek"或"复制模式（未配置 Key）"），点击进入设置。未配置 Key 时点 [开始批改]：弹出提示"未配置 API Key，已为你切换到复制模式"，并展开复制模式面板。
3. **报告区**（默认隐藏，批改后显示）
   - 评分卡：总分大号数字 `/15`、档次标签、四项分项进度条与分值。
   - 正文：步骤①~④ 四张分节卡片（标题严格匹配 `步骤① 总分与分项` 等四个标题）。
   - 工具条：批改中显示 [停止]；完成后显示 [打印/存为PDF] [导出 .md] [导出 .html] [重新批改]。
   - 流式输出说明：逐字渲染（节流 100 ms），自动跟随滚动；点击 [停止] 保留已生成的部分内容。
4. **设置抽屉**：服务商下拉（自动填充接口地址与默认模型）、API Key（密码框 + 显示/隐藏切换）、模型名（可编辑）、自定义接口地址（选"自定义"时出现）、[测试连接]（发一条 `max_tokens=1` 的最小请求）、[保存]、[清空全部本地数据]（二次确认）。Key 仅保存在浏览器 localStorage。
5. **历史记录抽屉**：列表项显示（时间、级别、题目或首句、总分）；操作：点击载入报告区、单项导出、删除、[全部清空]（二次确认）。空态与"历史仅存本机，建议导出重要报告"的提示文案。
6. **页脚**：免责声明（"批改结果由 AI 生成，仅供学习参考，不代表官方评分"）+ 隐私说明（"API Key 与作文只保留在你的浏览器；批改内容仅发送给你选择的 AI 服务"）+ 成本说明摘要。

### 5.2 主流程

```
填写级别/题目/作文（或图片）
        │
        ├─ 已配置 Key ──▶ [开始批改] ──▶ 流式生成 ──▶ 报告区（评分卡+四步骤）
        │                                              │
        └─ 未配置 Key ─▶ [复制批改指令] ─▶ 复制到任意 AI ─▶ 粘贴结果 ─▶ [渲染报告] ─▶ 同上
                                                       │
                                    导出（打印PDF / .md / .html）· 存入历史 · 重新批改
```

### 5.3 边界与错误状态（均须有明确界面表现）

| 状态 | 表现 |
|---|---|
| 作文为空 | 主按钮禁用 + 提示"请先粘贴作文或上传图片" |
| 词数偏离要求 | 徽章变色 + 提示（不阻止批改，由报告判断扣分） |
| 401 / Key 无效 | 报告区显示错误卡片，附"检查 Key"与"改用复制模式"两个按钮 |
| 402 余额不足 / 429 限流 | 对应文案 + 建议（充值 / 稍后重试 / 换服务商） |
| 网络失败 / CORS 失败 | 提示"无法连接服务商（可能网络受限）"，附"改用复制模式"按钮 |
| 120 s 超时 | 中止并提示重试 |
| 流中断 | 保留已生成内容并标注"生成中断" |
| 图片超限 | 拒绝并说明限制（≤3 张、单张 ≤8MB） |
| 无视觉能力模型 + 图片 | 阻止发起并提示换视觉模型（附推荐模型名） |
| 分数 JSON 解析失败 | 不显示评分卡，报告完整展示，附一行说明 |
| localStorage 不可用/已满 | 提示"历史保存失败（存储空间不足），请导出重要报告"；功能不中断 |

## 6. 批改引擎

### 6.1 提示词结构

**system 消息 = 批改模板原文（逐字保留 4 个步骤与 7 条硬性要求）+ 输出协议附录。**

输出协议附录全文（构建时以此为准）：

> 【输出协议（网页渲染要求，必须严格遵守）】
> 1. 你的回复必须以一个 JSON 代码块开头，且只有这一个 JSON 代码块。格式如下（全部为整数；`content` ≤5、`structure` ≤4、`vocab` ≤3、`grammar` ≤3，四项之和必须等于 `total`；`tier` 取值为"13-15分档 / 10-12分档 / 7-9分档 / 4-6分档 / 1-3分档"之一）：
>    ```json
>    {"total": 12, "tier": "10-12分档", "content": 4, "structure": 3, "vocab": 2, "grammar": 3}
>    ```
> 2. JSON 代码块之后紧跟完整批改报告。报告必须且只能使用以下四个 Markdown 二级标题（`## `），标题文字不得更改：
>    `## 步骤① 总分与分项`、`## 步骤② 逐条扣分点`、`## 步骤③ 修改建议`、`## 步骤④ 优化版本`
> 3. 报告中不使用 Markdown 表格、HTML 标签和图片；引用学生原文句子用 Markdown 引用块（`> `）；引用英文原句保持原文，不修改。
> 4. 字数是否达标，以下面"网页统计词数"为准，不要自行重新统计。
> 5. 步骤①②③的讲解全部使用中文；英文仅出现在原文引用、步骤④优化文本及必要的术语中。
> 6. 遵守模板中的全部硬性要求，包括步骤②必须引用原文原句、不得编造。

**user 消息 = 元信息 + 作文**，与批改模板的表头对齐：

```
【考试级别】四级
（选"自动推断"时写作：未提供，请依据作文内容推断，并先说明你的推断）
【作文题目】...（未提供时写作：未提供）
【网页统计词数】143 词（四级要求 120-180 词）
【学生作文】
"""
<正文或"（见附图，共 N 张）">
"""
```

有图片时使用 OpenAI 兼容的多模态消息格式：图片以 base64 data URL 放在 `image_url` 内容块中（详见 §6.4）。

### 6.2 服务商预设（经本机实测，全部支持浏览器直连）

实测方法：带 `Origin: https://example.github.io` 的 CORS 预检请求。实测结果：

| 服务商 | 接口地址 | 预检实测 | 备注 |
|---|---|---|---|
| **DeepSeek（默认）** | `https://api.deepseek.com` | ✅ 200，回显 Origin | 默认 `deepseek-chat`；无视觉 |
| Kimi（Moonshot） | `https://api.moonshot.cn/v1` | ✅ 204，回显 Origin | 默认 `moonshot-v1-8k`；视觉模型：`kimi-latest` |
| 通义（DashScope 兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | ✅ 200，`*` | 默认 `qwen-plus`；视觉：`qwen-vl-max` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | ✅ 200，回显 Origin | 默认 `glm-4-plus`；视觉：`glm-4v-plus` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | ✅ 204，`*` | 默认 `deepseek-ai/DeepSeek-V3`；视觉：`Qwen/Qwen2.5-VL-72B-Instruct` |
| OpenRouter | `https://openrouter.ai/api/v1` | ✅ 204，`*` | 模型名自填（如 `openai/gpt-4o-mini`） |
| OpenAI | `https://api.openai.com/v1` | ⚠️ 本网络不通 | 标注"需代理"；默认 `gpt-4o-mini`（视觉） |
| 自定义 | 用户填写 | —— | OpenAI 兼容协议即可 |

说明：
- 一律使用 **OpenAI 兼容协议**（`POST /chat/completions`），不实现 Anthropic 原生协议；需要 Claude 的用户可通过任意 OpenAI 兼容网关（如 one-api 类）走"自定义"接入。
- 预设模型名是**默认值**，界面中模型字段可编辑（模型名会随服务商更新变化；README 中说明）。
- 预设表集中维护在 `assets/js/providers.js`，每项含：名称、baseURL、默认模型、视觉能力标记、备注。

### 6.3 请求与流式输出

- `POST {baseURL}/chat/completions`，`stream: true`；`Authorization: Bearer {key}`。
- 参数：`temperature: 0.6`、`max_tokens: 8192`。若返回 400 且错误信息涉及参数不支持，自动去除该参数重试一次。
- SSE 解析：按行处理 `data:` 前缀，忽略注释行与空行，遇 `[DONE]` 结束；需正确处理跨 chunk 的分包与同一事件多行 data（这是单测重点）。
- 若服务商拒绝 `stream: true`，自动退回非流式一次性请求。
- `AbortController` 支持 [停止]；超时 120 s。
- 增量渲染节流 100 ms；报告区自动滚动到底部。

### 6.4 图片处理

- 最多 3 张；原图 ≤ 8MB/张，超出即拒绝并提示。
- 前端用 canvas 压缩：长边 ≤ 1600 px，JPEG 质量 0.85，再转 data URL，控制 token 成本。
- 所选服务商预设无视觉能力时：禁用图片上传并提示（附该服务商的视觉模型名或建议换服务商）。
- 有图片且模型支持视觉时，user 消息内容块为 `[{type:"text", ...}, {type:"image_url", image_url:{url:"data:image/jpeg;base64,..."}}, ...]`。

### 6.5 API Key 与隐私

- 仅存 `localStorage`（`eec.settings.v1`）；密码输入框默认遮蔽，提供显示切换。
- 仅在向所选服务商发起请求时使用；无任何上报、无第三方请求。
- [测试连接]：发送 `max_tokens: 1` 的最小请求验证 Key 与连通性。
- [清空全部本地数据]：清除设置与历史（二次确认）。

### 6.6 错误分类

`api.js` 将失败映射为可显示的错误类型：`auth`（401/403）、`balance`（402）、`rate`（429）、`params`（400，自动重试一次后仍失败）、`network`（fetch 失败 / CORS）、`timeout`、`aborted`、`server`（5xx）。每类对应固定中文文案与行动建议按钮（§5.3）。

## 7. 输出协议与渲染

### 7.1 分数块解析（`prompt.js`）

1. 主路径：提取回复中第一个 ```json 围栏内容 → `JSON.parse`（容错：先截取首 `{` 至末 `}`）→ 校验字段与范围（`total` 0–15 且等于四项之和；分项不超上限）。
2. 备用路径：从"步骤①"文本正则提取"总分：X / 15"与各分项数字。
3. 终态降级：两者都失败 → 不渲染评分卡，报告照常完整展示，卡片位置显示一行"未解析到结构化分数"。

### 7.2 Markdown 渲染器（`render.js`，白名单）

- **流程：先对全文 HTML 转义，再按行/行内规则生成受限 DOM**，绝不直接插入未转义内容。
- 支持子集：`#`~`####` 标题、`**粗体**`、`*斜体*`、行内代码、围栏代码块、有序/无序列表（含一层嵌套）、`>` 引用块、`---` 分隔线、`[文本](http/https)` 链接（新窗口打开、`rel="noopener"`）、段落与换行。
- 不支持：表格、HTML 标签、图片（`![]()` 渲染为纯文本），未知语法按普通文本展示。
- 四个步骤标题渲染为分节卡片；其余标题降为样式化小标题。

### 7.3 评分卡

- 展示：总分（大号数字 `/15`）、档次标签（映射：13-15 / 10-12 / 7-9 / 4-6 / 1-3）、四项分项（名称 + 得分/满分 + 进度条）。
- 分数经 §7.1 校验后展示；数据异常时降级并标注。

## 8. 字数统计

- 统计规则：匹配 `[A-Za-z]+(?:['’-][A-Za-z]+)*`（正确处理 `don't`、`well-known` 等），与"以空格分词"相比更准确。
- 达标区间：四级 120–180 词；六级 150–200 词（与批改模板一致）。
- 统计结果注入提示词（§6.1 的【网页统计词数】）。

## 9. 复制模式

- 组装为**单条文本**（用户复制一次即可）：
  ```
  请你严格按照以下要求，批改下面这篇大学英语四六级作文。请先完整阅读全部要求，再一次性输出完整报告。

  ===== 批改要求（必须全部遵守）=====
  <批改模板原文 + 输出协议附录>

- 附一行建议："推荐使用 DeepSeek 网页版 / Kimi / 豆包 / 通义 / ChatGPT 免费版等任意 AI 对话服务，全程免费。"
- 复制模式得到的报告与自动模式**共用同一渲染、评分卡、导出与历史逻辑**（历史来源标记 `paste`）。
- 复制模式不支持图片（AI 聊天服务可自行发图，指令中会提示）。

## 10. 导出

1. **打印 / PDF**：`@media print` 专用样式——A4、边距 18mm、隐藏所有交互元素与输入区、仅保留报告；报告头部显示（产品名、日期、级别、题目、总分与档次）；分节卡片避免跨页断裂。
2. **Markdown（.md）**：文件头为元信息 + 分数块的 Markdown 表格化摘要 + 报告原文。
3. **独立 HTML（.html）**：单文件、样式内联、无任何脚本、离线可打开；包含评分卡与完整报告；页脚含免责声明。文件名：`批改报告_YYYY-MM-DD_级别_题目(截断).html`。
4. 历史记录中任一报告均可重复上述导出。

## 11. 历史记录

- 存储键：`eec.history.v1`（数组）。
- 单条字段：`{ id, ts, level, title, words, scores(可空), essay, reportMd, source: 'auto' | 'paste' }`。
- 上限 100 条，超出删除最旧；写入失败（配额）时提示且不中断批改。
- 操作：载入报告区、单项导出、单项删除、全部清空（二次确认）。

## 12. 部署

1. 仓库：`github.com/AWua-Dcm/English-Essay-Correction`，**公开**（免费版 GitHub Pages 要求公开仓库）。
2. 分支：`main`，从**根目录**发布；保留 `.nojekyll`。
3. 推送：本机 Git Credential Manager 已存 AWua-Dcm 凭据，`git push` 可自动认证。仓库创建优先尝试用已存凭据调用 GitHub API；若失败，则请用户在浏览器点 "New repository"（30 秒，同名、公开、不带任何初始化文件），然后本地推送。
4. 启用 Pages：优先 API 开启（main / root）；若失败，请用户在 Settings → Pages 选择 "Deploy from a branch → main → / (root)"。
5. 更新流程：后续改动 `git push` 即自动重新发布。
6. **国内访问风险**：`github.io` 在国内可能访问不稳定。兜底方案（写入 README）：a) 下载仓库后双击 `index.html` 离线使用（复制模式完全可用）；b) 导出独立 HTML 报告分享。
7. 版权：默认不放 LICENSE（保留所有权利）；如用户需要开源协议再补。

## 13. 质量保障与验收（对应"自行审核网页完成度"）
