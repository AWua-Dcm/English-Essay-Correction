# 本地图片识别：实测数据与设计取舍

`assets/js/ocr.js` 让网页在**本地、离线、不需要 Key** 的情况下把作文图片转成文字。
这份文档记录为什么这么做，以及实测的能力边界。

---

## 1. 实测准确率

**测试方法**：词级准确率（1 − 词级编辑距离 / 参考词数），对照视觉模型转写的结果。
两组素材：

- **真实作文截图 14 张** —— 来自语料里的学生作文页面，每张都有对应的转写文本（`tools/ocr_accuracy.js`）
- **合成对照 3 张** —— 同样文字分别渲染成高清印刷体 / 低清印刷体 / 手写体，用来分离"分辨率"与"字体"两个变量

| 条件 | 词级准确率 | Tesseract 自评置信度 |
|---|---|---|
| 印刷体 · 2480px 高清 | **98.9%** | 95% |
| 印刷体 · 760px 低清 | 94.5% | 90% |
| 手写体 · 2480px 高清 | **75.8%** | 69% |
| **真实作文截图（14 张）** | **74.3%**（中位 85.3%，区间 32–98%） | — |

**真实截图那 74.3% 几乎等于手写体的 75.8%**，说明那批截图里相当一部分是手写卷面。
也就是说，限制因素是**字体**，不是分辨率。

顺带证伪了一个常见想法：**放大预处理没用**。3× LANCZOS 放大后准确率反而从 74.3% 降到 71.3%。

## 2. 结论：印刷体可用，手写体不可用

手机拍作文，拍到的**通常是手写卷面**。75.8% 的词准确率意味着 150 词的作文会错约 38 个词——
而批改的核心功能恰恰是**找语法和拼写错误**。识别错误会被当成学生作文里的错误扣分，
所以本地 OCR 在它最主要的场景里不是"没用"，而是**有害**。

因此本功能的设计是：

| 决定 | 原因 |
|---|---|
| **从不自动批改**，只把文字填进正文框 | 识别结果必须由用户过目 |
| 按置信度分三档提示（≥85 / 70–85 / <70） | 置信度与实测准确率高度相关（95%↔98.9%，69%↔75.8%），可当门控 |
| 低置信度明确**劝退**并给替代路径 | 手写场景要靠视觉模型，不该在这里硬扛 |
| **绝不自动纠正拼写** | 批改就是要找拼写错误，自动纠错等于先把要检测的错误抹掉 |
| 懒加载引擎（约 6.7MB 首次点击才下载） | 首屏不受影响；资源在仓库内，不请求第三方 |

## 3. 为什么不自己训练检测模型

常见想法是"训练一个 YOLO 再放进网页"。**YOLO 是检测模型，不是识别模型**——
它回答"文字在哪"（画框），不回答"写的是什么"。OCR 需要两步：

```
检测（YOLO / DBNet / CRAFT）→ 识别（CRNN+CTC / TrOCR / SVTR）
```

- **格式转换本身没问题**：Ultralytics 导出 ONNX，用 `onnxruntime-web` 在浏览器跑（WASM/WebGPU），是成熟做法。YOLOv8n 的 ONNX 约 12MB（fp32）/ 3MB（int8）。
- **但瓶颈在"读"不在"找"**：通用识别模型在手写上的表现和 Tesseract 差不多（都为印刷体训练）。
  要把手写做到 90%+，需要用**手写数据专门训练识别模型**（IAM / CASIA-HWDB 之类），
  通常要 TrOCR 级别的模型——fp32 约 330MB、int8 约 80MB，**静态页扛不住**。
- YOLO 真正能帮上忙的地方是另一个：照片背景杂乱时**框出作文区域、切分文本行**，
  但那是预处理优化，不解决"读手写"。

**所以这是训练问题，不是打包问题。** 图片作文的正路仍是视觉模型：
自动模式配视觉模型 / 复制模式粘到会看图的免费 AI / Claude Code skill 用 Read 读图。

## 4. 引擎变体：一个必须知道的坑

tesseract.js 的 worker 会按能力探测顺序请求核心文件：

```
relaxedsimd → simd → 无 SIMD
  ↓            ↓        ↓
relaxedsimd-lstm.wasm.js / simd-lstm.wasm.js / lstm.wasm.js
```

**只 vendor 其中一个变体，自动探测就会 404**（现代 Chrome 支持 relaxed SIMD，会请求第一个）。
但同一段代码里有一句：`corePath` 以 `js` 结尾时**原样使用**。所以 `ocr.js` 直接把
`corePath` 钉到单个文件，跳过整套探测，只需 vendor 一个变体（3.72MB 而非 11MB）。

代价：需要浏览器支持 **WASM SIMD**（Chrome 91+ / Firefox 89+ / Safari 16.4+，2026 年已是基线）。
不支持时会明确报错并给出替代路径，不会静默失败。

## 5. 复现

```bash
npm install --no-save tesseract.js @tesseract.js-data/eng
node tools/ocr_accuracy.js          # 真实作文截图的词级准确率
node corpus/_ocr_test/run_syn.js    # 印刷体/低清/手写三组对照（需先生成合成图）
```

合成对照图的生成脚本见本文件第 1 节所述方法（PIL 渲染同一段文字为三种条件）。
注意画布高度必须容纳全部行——第一次测量时因画布裁掉最后一行，得到了偏低的假数字。
