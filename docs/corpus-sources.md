# 四六级作文语料来源地图

这份文档记录**怎样重新采集**四六级作文语料。它不含任何范文正文，只有来源、URL 形态与实测结论，
因此适合提交进仓库；范文正文本身只存在本地 `corpus/`（已被 `.gitignore` 忽略），提炼完即可删除。

文档里的每条结论都来自**实际抓取验证**，不是搜索结果推断。

---

## 1. 环境前提（踩过的坑）

| 事实 | 后果 |
|---|---|
| `WebFetch` 在本环境**全域名失效**（域名安全校验服务不可达，连 wikipedia 也失败） | 一律改用 `curl` |
| `WebSearch` 正常 | 用它找页面 |
| 本机网络为**中国大陆出口**：中文站 200，`example.com` 超时 | 目标站都可达，海外站可能不可达 |
| Windows 控制台为 cp936 | **禁止把中文当命令行参数**（会被转码损坏）；中文写进脚本文件或用 `\uXXXX` |
| 部分站点正文是**图片** | 需 `harvest.py images` + `Read` 识读 |

## 2. 工具链（`tools/`）

```
harvest.py  fetch / text / images —— 抓取、解码、去标签、图片列举
crawl.py    page / batch        —— 把页面切成候选作文（行级抽取）
urls.py     build               —— 走分页索引页收集文章 URL
store.py    merge / stats       —— 校验、去重、归档、出缺口报告
analyze.py  features / bands / contrast —— 按档提特征并做单调性检验
validate.py split / score       —— 盲评校验（剥分数 → 盲判 → 比对）
```

抽出来的正文**只是候选**，不是入库记录。候选必须经过判档/判定主题才算数。

## 5. 分档标注的真实分布（关键结论）

**公开范文绝大多数不标分数。** 实测能拿到明确标分的文字范文只有：

- `cet4.koolearn.com/20151125/797819.html` = **11分**，`797820` = **8分**，`797821` = **5分**，`797822` = **2分**
  （四篇同一题目：How Should Parents Help Children to Be Independent）
- `mtoutiao.xdf.cn` 的 `14分档` 逐段拆解样文
- `dioenglish.com/writing/englishtest/cet6/66047.html` = **11分 / 8分** 同题对比

**带官方精确分数的样卷（14/11/8/5/2）全网以图片流传**，要拿到就得走 `harvest.py images` + `Read` 识读。

因此语料分两类，不可混淆：

| 类别 | `corpus_class` | 含义 |
|---|---|---|
| 带标注 | `labeled` | 来源明确写了分数；**可作校验基准** |
| 范文 | `model` | 机构发布的参考范文，**按体裁推定高分档**，不是 ground truth |

`model` 类可用于描述"高水平写作长什么样"（特征分布），但**不能当作评分真值**。

## 6. 抽取时踩过的坑（改 `crawl.py` 时注意）

1. **行级抽取，不要段落级**：koolearn 等站把中文注解和英文正文放在**同一个段落**里，段落级过滤会把正文一起丢掉。
2. **硬换行会导致碎片**：koolearn 约每 13 词换行、51test 约每 40 字符换行，且换行后下一行可能**大写开头**——
   判据必须是"上一行没有句末标点"，不能依赖大小写。
3. **中英标点混用**：koolearn 用中文句号结束英文句子（`...very happy。`），需归一化。
4. **先切分、后过滤**：混合页会把多篇作文和听力答案连成一个超长 run，整段判非作文会连带丢掉好作文。
   超长 run 必须按句边界切开再逐块判断。
5. **同一篇作文被多页重复发布**（"热门话题"页与"必考话题"页常同一篇），必须去重。

## 7. 实测产量基线

- koolearn 四级归档 269 URL → **239 候选**（89%）
- koolearn 六级归档 266 URL → **251 候选**
- 合并去重后 **425 篇唯一作文**（丢弃 77 篇重复），中位词数 187

这个产量是在**几乎没有消耗模型 token** 的情况下拿到的：搜索才是贵的一环（实测每个搜索型 agent 约 14 万 token），
所以正确做法是**先侦察出源清单，再机械抓取**，把模型 token 只花在"判档、切分、复核"这些真正需要判断的地方。
